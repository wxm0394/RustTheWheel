# 骑马与砍杀早期 MOD 移植到战团 — 移植项目需求文档

> 本文档基于本地文件调查编写，所有结论标注证据等级：**已确认**（有直接本地证据）、**推断**（有间接证据但未运行验证）、**待确认**（证据不足或矛盾）。配套文档见 [`本地资产调查报告.md`](本地资产调查报告.md) 与 [`待确认事项.md`](待确认事项.md)。

## 1. 项目目标

### 1.1 总目标

将 RustTheWheel（以下简称 RTW）和 Splatterhouse（以下简称 SPL）两个早期 MOD，分别移植到《骑马与砍杀：战团》1.174，形成两个独立的战团 MOD。

### 1.2 具体目标

- **RTW**：将原版 1.011 时期的单人战役 MOD 移植为战团 1.174 单人 MOD，恢复其可确认的核心玩法与内容。
- **SPL**：将已部分适配战团的 MOD 完整迁移到战团 1.174 Module System 基线，恢复其可确认的核心玩法与内容。
- 优先恢复原作可确认的核心玩法与内容。
- 原作行为修复、玩法重做、历史化改造属于独立需求，不默认包含。

### 1.3 不包含

- 不修改、删除、覆盖现有源码、游戏配置、编译产物或原始资源。
- 不在原始 MOD 目录或 Native 目录上直接开展移植。
- 不执行未知 EXE、安装程序或压缩包内程序。
- 不承诺旧存档兼容、资源完全兼容或功能完全等价。

## 4. 项目范围

### 4.1 本轮移植包含

- 将两个 MOD 的编译 TXT 数据迁移到战团 1.174 Module System 源码基线。
- 将两个 MOD 的自定义资源（BRF、DDS、SCO、OGG）迁移到战团兼容格式。
- 恢复原作可确认的核心玩法与内容。
- 确保两个 MOD 在战团 1.174 下可加载、可进入游戏。

### 4.2 本轮移植不包含

- 原作行为修复、玩法重做、历史化改造（独立需求）。
- 联网多人服务端搭建与测试（仅在联网玩法得到确认后纳入）。
- 旧存档兼容。
- 公开发布（授权待确认）。

### 4.3 必需项

- 两个独立工作目录，与原始资料隔离。
- 目标战团 Module System 基线（`module_system_1174/`）。
- TXT → Python 源码的数据提取与逻辑恢复。
- 资源引用与文件大小写检查。

### 4.4 条件性需求

- **SPL 联网**：仅在确认 SPL 确有真正联网机制后，才纳入客户端/服务端相关需求。当前证据为**推断**，不默认规划为战团多人模块。
- **Python 2 环境**：Module System 为 Python 2 语法，系统 Python 为 3.14.7，需准备 Python 2 运行环境才能编译。

### 4.5 可选改进

- 中文本地化（两个 MOD 均有 cns/cnt 语言文件）。
- 资源优化（BRF 重新打包、纹理压缩）。

## 6. 技术需求

### 6.1 独立工作目录与原始资料保护

- 移植工作在独立目录进行，不修改 `RustTheWheel026-3795--026.zip`、`Splatterhouse.zip`、`native_1010/`、`Native_1174/`、`module_system_1174/` 中的任何文件。
- 原始压缩包解压到新增的调查目录，禁止覆盖既有文件。
- 建议目录结构：
  ```
  RustTheWheel_port/     # RTW 移植工作目录
  Splatterhouse_port/    # SPL 移植工作目录
  investigation/         # 调查解压目录
  ```

### 6.2 目标 Module System 基线及构建方式

- 目标基线：`module_system_1174/`（战团 1.174 Module System）。
- 构建方式：`build_module.bat`（Windows）或等效 Linux 命令行逐个调用 `python process_*.py`。
- `build_module.bat` 依次调用 30 个 `process_*.py` 脚本（`process_init.py` → `process_postfx.py`），最终输出编译 TXT 到 `module_info.py` 中 `export_dir` 指定的目录（当前值为 `"../py3_out/"`）。
- **已确认**：`module_system_1174/header_operations.py` 共 1901 行，`native_1010/ModuleSystem/header_operations.py` 共 1130 行——战团操作码定义比原版多约 770 行，存在大量新增操作码。
- **已确认**：`module_system_1174/build_module.bat` 比 `native_1010/ModuleSystem/build_module.bat` 多调用 `process_info_pages.py` 和 `process_postfx.py`（战团新增模块）。

### 6.3 编码与路径约定

- Module System Python 源码文件均为 **UTF-8 无 BOM** 编码（**已确认**：`file` 命令检测）。
- 编译后 TXT 文件编码为 **Windows-1252 / Latin-1** 系（含中文时使用 GBK 或 UTF-8，视 MOD 而定）。
- `module_info.py` 中 `export_dir` 使用正斜杠 `/`（跨平台兼容），移植时需修改为实际输出目录。
- Linux 下文件系统大小写敏感，Windows 下不敏感——MOD 中 BRF/DDS/SCO 文件名大小写需逐一核对，避免在 Linux Wine 下加载失败。
- **待确认**：RTW 和 SPL 的 TXT 文件实际编码（GBK / UTF-8 / Windows-1252）。

### 6.4 资源引用完整性

- `module.ini` 中的 `load_resource`（公共 BRF）和 `load_mod_resource`（MOD 自有 BRF）声明需与实际 BRF 文件一一对应。
- 物品 `item_kinds1.txt` 中的 mesh 引用需在 BRF 中存在。
- 场景 `scenes.txt` 中的 scene_prop 引用需在 `scene_props.txt` 和对应 BRF 中存在。
- **已确认**：RTW `module.ini` 声明 11 个 `load_mod_resource`；SPL `module.ini` 声明大量 `load_resource`（战团公共 BRF）+ `load_mod_resource = blood`。
- **待确认**：所有 mesh/texture 引用是否在对应 BRF 中实际存在（需用 OpenBRF 工具检查，当前环境无此工具）。

### 6.5 数据 ID 与索引连续性

- Module System 编译时，各数据表（troops、items、factions、scenes、scripts 等）按 Python 源码中的列表顺序生成从 0 开始的连续整数 ID。
- TXT → Python 恢复时，必须保持原始顺序不变，否则 ID 偏移会导致脚本中硬编码引用错乱。
- 战团新增的数据表（`info_pages`、`postfx`）在原版 1.011 中不存在，RTW 移植时需新增空表或战团默认值。
- **已确认**：RTW troops 588 条、items 596 条、factions 25 条；SPL 有 49 mission_templates、24 triggers。
- **待确认**：RTW/SPL 的 scripts.txt 中是否存在硬编码 ID 引用（需逐条分析脚本逻辑）。

### 6.6 脚本迁移边界

- `scripts.txt` 中的每个脚本对应 Module System `module_scripts.py` 中的一个函数定义。
- 脚本内部使用操作码（opcode）序列，原版 1.011 和战团 1.174 的操作码编号可能不同。
- **已确认**：`header_operations.py` 从 1130 行（1.011）增长到 1901 行（1.174），新增操作码可能导致编号偏移。
- TXT 中的操作码为数字，需对照对应版本的 `header_operations.py` 反查操作名称，再写入战团 Python 源码。
- **待确认**：是否存在原版 1.011 有但战团 1.174 已移除的操作码（若存在，需寻找替代实现）。

### 6.7 场景文件兼容性

- 场景文件为 `.sco` 格式（Scene Object），存储地形、物体放置、场景属性等。
- **已确认**：RTW 有 30+ SCO 文件（`SceneObj/` 目录）；SPL 的 SCO 数量待统计。
- **待确认**：原版 1.011 SCO 格式与战团 1.174 SCO 格式是否二进制兼容。若不兼容，需用对应版本编辑器重新保存或手动重建。
- 场景中引用的 scene_prop 和 mesh 必须在战团下存在。

### 6.8 构建、部署与回滚

- **构建**：在独立工作目录中修改 `module_info.py` 的 `export_dir`，运行 `build_module.bat` 或等效 Linux 命令，输出编译 TXT。
- **部署**：将编译 TXT + 资源文件（BRF/DDS/SCO/OGG）+ `module.ini` 复制到战团 Modules 目录下的独立子目录。
- **回滚**：每次构建前用 Git 提交当前状态；部署前备份战团 Modules 目录；失败时删除部署目录并回退 Git。
- **已确认**：当前项目目录非 Git 仓库，需初始化。
- **待确认**：战团游戏实际安装路径（GOG 安装包未安装）。

### 6.9 联网需求（仅 SPL，条件性）

- **当前状态**：SPL 有 8 个多人任务模板和 `multiplayer_server_*` 脚本，但未验证实际联网运行。**不默认规划联网架构。**
- **条件触发**：仅在用户确认 SPL 需要联网功能、且验证战团 1.174 多人模式可用后，才纳入以下需求：
  - 战团多人 Module System 架构（`module_mission_templates.py` 中的 `multiplayer_*` 模板）。
  - `module.ini` 中 `compatible_multiplayer_version_no` 设置。
  - 多人场景、多人物品、多人部队的独立数据表。
- **待确认**：SPL 是否真正支持网络联机；`multiplayer_server_*` 脚本是否为战团原生模板的残留。
