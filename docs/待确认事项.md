## 阻断级（不解决则无法推进移植）

### TC-001：Python 2 运行环境缺失

| 维度 | 内容 |
|------|------|
| **问题** | Module System 的 `process_*.py` 脚本为 Python 2 语法，当前系统仅有 Python 3.14.7，无法直接运行编译流程。 |
| **当前证据** | `python3 --version` = 3.14.7（**已确认**）；`module_system_1174/build_module.bat` 调用 `python process_init.py` 等 30 个脚本（**已确认**）；Module System 源码使用 `print` 语句（Python 2 语法）而非 `print()` 函数（**已确认**）。 |
| **影响范围** | **阻断全部移植工作**——无法编译 Module System，无法生成战团 TXT。 |
| **建议验证方法** | 1. 尝试 `python2 --version` 或 `python2.7 --version` 确认系统是否已有 Python 2；2. 安装 Python 2.7（`pyenv install 2.7.18` 或 `conda create -n py2 python=2.7`）；3. 在 `module_system_1174/` 中运行 `python2 process_init.py` 验证可执行。 |
| **替代方案** | 评估用 `2to3` 工具将 Module System 转换为 Python 3 兼容代码的可行性（需逐文件检查兼容性）。 |

### TC-003：TXT → Python 源码恢复工具缺失

| 维度 | 内容 |
|------|------|
| **问题** | 两个 MOD 均无 Python 源码，仅有编译后 TXT。移植到战团 Module System 需从 TXT 反向恢复 Python 源码，但当前无可用反编译工具。 |
| **当前证据** | RTW 压缩包内无 `module_*.py` 文件（**已确认**）；SPL 压缩包内无 `module_*.py` 文件（**已确认**）；系统无已知 M&B TXT 反编译工具（**已确认**）。 |
| **影响范围** | **阻断核心移植**——无法将 MOD 逻辑迁移到战团 Module System Python 源码。 |
| **建议验证方法** | 1. 搜索社区反编译工具（如 `mb_decompiler`、`mb_txt_to_py` 等）；2. 评估工具对战团 1.174 TXT 格式的兼容性；3. 若无可用工具，需手动逐条解析 TXT（工作量极大）。 |
| **替代方案** | 评估直接编辑 TXT（不经过 Python 源码）的可行性——适用于纯数据迁移（troops/items/factions），但脚本逻辑（scripts/triggers/dialogs）难以手动编辑。 |

## 高严重度（不解决则移植质量/完整性无法保证）

### TC-004：SPL 实际联网能力未验证

| 维度 | 内容 |
|------|------|
| **问题** | SPL 有 8 个多人任务模板和 `multiplayer_server_*` 脚本，但未验证是否真正支持网络联机。用户称"联机、无单机"，但本地证据显示有完整单人战役结构，存在矛盾。 |
| **当前证据** | `Splatterhouse/mission_templates.txt` 含 `mst_multiplayer_dm`、`mst_multiplayer_tdm`、`mst_multiplayer_hq`、`mst_multiplayer_cf`、`mst_multiplayer_sg`、`mst_multiplayer_bt`、`mst_multiplayer_fd`、`mst_multiplayer_duel`（8种）（**已确认**）；scripts 含 `multiplayer_server_on_agent_spawn_common`、`multiplayer_server_player_joined_common`（**已确认**）；`Splatterhouse/menus.txt` 含 `menu_start_game_0`、`menu_start_phase_2`（完整单人战役）（**已确认**）；用户描述"联机、无单机"与本地证据矛盾（**已确认**）。 |
| **影响范围** | **影响 SPL 移植架构**——若确有联网需求，需规划战团多人 Module System 架构；若无，则移除多人模板避免无效工作。 |
| **建议验证方法** | 1. 在战团下加载 SPL，尝试启动多人模式，观察是否有服务器列表/创建服务器选项；2. 检查 `module.ini` 中 `compatible_multiplayer_version_no` 字段（SPL 的 module.ini 中此字段值待确认）；3. 对比 SPL 多人模板与战团 Native 多人模板的差异，判断是否为原生残留。 |
| **当前处理策略** | **不默认规划联网架构**。单人模式移植优先；联网作为条件性需求（SPL-F-003）。 |

### TC-005：原版 1.011 与战团 1.174 操作码差异

| 维度 | 内容 |
|------|------|
| **问题** | RTW 的 scripts/triggers/dialogs 使用原版 1.011 操作码编号，战团 1.174 的操作码编号可能不同（新增操作码可能导致编号偏移），直接移植可能导致脚本逻辑错乱。 |
| **当前证据** | `native_1010/ModuleSystem/header_operations.py` 共 1130 行（**已确认**）；`module_system_1174/header_operations.py` 共 1901 行（**已确认**）；差异约 770 行（**已确认**）。 |
| **影响范围** | **影响 RTW 和 SPL 的全部脚本/触发器/对话**——操作码编号不匹配会导致运行时行为异常或崩溃。 |
| **建议验证方法** | 1. 逐操作码对比两个版本 `header_operations.py` 中的操作定义，建立编号映射表；2. 重点检查是否存在编号重排（而非纯追加）；3. 检查是否存在原版有但战团已移除的操作码。 |
| **备注** | SPL 已有 `compatible_with_warband = 1`，可能已部分适配战团操作码，但 `works_with_version_max = 1011` 暗示可能仍有原版残留。 |

## 中严重度（影响移植完整性但不阻断核心流程）

### TC-008：SPL `works_with_version_max = 1011` 与 `compatible_with_warband = 1` 的矛盾

| 维度 | 内容 |
|------|------|
| **问题** | SPL 的 `module.ini` 同时声明 `compatible_with_warband = 1`（战团兼容）和 `works_with_version_max = 1011`（最高支持原版 1.011），两者含义矛盾。 |
| **当前证据** | `Splatterhouse/module.ini` 第2行 `compatible_with_warband = 1`（**已确认**）；`Splatterhouse/module.ini` 末尾 `works_with_version_max = 1011`（**已确认**）。 |
| **影响范围** | **影响 SPL 移植策略**——若 SPL 实际为原版 1.011 MOD 仅添加了战团兼容标记，则需按原版→战团移植处理；若已真正适配战团，则迁移工作量较小。 |
| **建议验证方法** | 1. 对比 SPL 的 TXT 格式与 `Native_1174/` 和 `native_1010/Native/` 的格式差异；2. 检查 SPL scripts 中的操作码编号属于哪个版本；3. 在战团下实际加载 SPL 观察是否正常运行。 |

### TC-009：RTW 特殊玩法文件功能

| 维度 | 内容 |
|------|------|
| **问题** | RTW 压缩包含 `DartsRules.txt`、`Recipes.txt`、`Ranks.txt` 等特殊文件，但未确认其在游戏中的实现方式。 |
| **当前证据** | 压缩包文件列表含上述文件（**已确认**）；未阅读文件内容（**待确认**）；未在 scripts.txt 中搜索相关引用（**待确认**）。 |
| **影响范围** | **影响 RTW 玩法完整性**——若这些文件定义了核心玩法机制（如飞镖游戏、合成系统、军衔系统），遗漏会导致玩法缺失。 |
| **建议验证方法** | 1. 阅读三个 TXT 文件内容；2. 在 `scripts.txt`、`triggers.txt`、`menus.txt` 中搜索 "Darts"、"Recipe"、"Rank" 等关键词；3. 确认这些机制是否通过脚本实现。 |

### TC-010：TXT 文件实际编码

| 维度 | 内容 |
|------|------|
| **问题** | RTW 和 SPL 的 TXT 文件编码未确认（GBK / UTF-8 / Windows-1252），影响数据提取时的字符正确性。 |
| **当前证据** | 未用 `file -i` 或 `chardet` 检测 TXT 编码（**待确认**）。 |
| **影响范围** | **影响中文文本正确性**——编码错误会导致中文乱码，影响对话、菜单、物品名称等。 |
| **建议验证方法** | 1. 对每个 MOD 的关键 TXT 文件运行 `file -i`；2. 用 `chardet` 检测编码；3. 确认中文内容（cns/cnt 语言文件）的编码。 |

### TC-012：战团新增数据表的适配

| 维度 | 内容 |
|------|------|
| **问题** | 战团 1.174 新增了 `info_pages` 和 `postfx` 数据表，原版 1.011 MOD 中不存在这些表，移植时需决定如何处理。 |
| **当前证据** | `module_system_1174/build_module.bat` 调用 `process_info_pages.py` 和 `process_postfx.py`（**已确认**）；`native_1010/ModuleSystem/build_module.bat` 不调用这两个脚本（**已确认**）；`Native_1174/info_pages.txt` 存在而 `native_1010/Native/` 中不存在（**已确认**）。 |
| **影响范围** | **影响编译流程**——若 Python 源码中缺少 `module_info_pages.py` 或 `module_postfx.py`，编译可能失败。 |
| **建议验证方法** | 1. 检查战团 Module System 中这两个文件是否可为空表；2. 参考 `Native_1174/info_pages.txt` 和 `Native_1174/postfx.txt` 的内容决定是否需要填充默认值。 |
